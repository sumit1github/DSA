
# What is Time Complexity?
Time complexity = How runtime grows as input size (n) grows.

We don't care about exact seconds (depends on hardware). We care about growth rate — what happens when n goes from 10 → 10,000 → 1,000,000?

# Comparison (must need to remember)

FASTEST TO SLOWEST (Memorize this order):

```O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)```

## what is n
n = size of input

### 🎯 The "Daily Life" Big O Memory Table

### Complete Reference for Python Developers

| Big O | Visual Analogy | Python Code You Know | Remember By |
|-------|---------------|---------------------|-------------|
| **O(1)** | Finding a book on your desk by its exact spot | `dict.get()`, `arr[0]` | **"One shot"** — you know exactly where it is |
| **O(log n)** | Finding a word in a dictionary (open middle, decide left/right) | Binary search, heap operations | **"Log" as in "look"** — you look, split, repeat |
| **O(n)** | Reading every page of a book once | `for x in arr`, `sum()` | **"N stands for need"** — need to check everything |
| **O(n log n)** | Organizing a deck of cards (split, sort, merge) | `sorted()`, Merge Sort | **"Efficient sorting"** — like organizing your files |
| **O(n²)** | Comparing every student with every other student in class | Nested loops, bubble sort | **"Square"** — imagine a square grid of comparisons |
| **O(2ⁿ)** | Double the work for each new item (like chain emails that double) | Recursive Fibonacci (without memo) | **"Exponential explosion"** — like virus spread |
| **O(n!)** | Arranging n people in all possible seating orders | Permutations generator | **"Factorial nightmare"** — 10! = 3.6 million |

---

## Quick Reference: Speed Order

## Complete Mathematical Reference

| g(n) | Name | Mathematical Characteristics | Visual Analogy |
|------|------|------------------------------|----------------|
| **1** | Constant | Always the same, doesn't depend on n | "One shot" — never changes |
| **log n** | Logarithmic | Doubling n adds a constant amount of work | "Look" — split and search |
| **n** | Linear | Doubling n doubles the work | "Need" — scan each element |
| **n log n** | Linearithmic | Doubling n slightly more than doubles the work | "Sort" — efficient sorting |
| **n²** | Quadratic | Doubling n quadruples the work | "Square" — nested loops |
| **n³** | Cubic | Doubling n multiplies work by 8 | "Cube" — triple nested loops |
| **2ⁿ** | Exponential | Adding 1 to n doubles the work | "Explode" — chain reaction |
| **n!** | Factorial | Adding 1 to n multiplies work by (n+1) | "Never" — impossible for large n |

---

## 🎯 Mathematical Characteristics Explained

### O(1) — Constant

```
When n = 100:

O(1)     = 1
O(log n) = log₂(100) ≈ 6.64
O(n)     = 100
O(n log n) = 100 × 6.64 = 664
O(n²)    = 100² = 10,000
O(2ⁿ)    = 2¹⁰⁰ ≈ 1.27 × 10³⁰  (astronomical!)
O(n!)    = 100! ≈ 9.33 × 10¹⁵⁷ (impossible!)
```

## Logrithmic Time Complexity 
 
#### Example 1
```
n=10

while(n>=1):
print(hello)
    n=n//2

------------
**Time Complexity:** O(log n)

**How to Derive:**
- n = 10 → 10, 5, 2, 1 (4 steps)
- n = 100 → 100, 50, 25, 12, 6, 3, 1 (7 steps)
- Each step divides n by 2

# hwo to derive
let the loop will run for K times => time complexity is O(k)

n/2, n/4, n/8, .............. n/2^k

                or 

n/2^1, n/2^2, n/2^3, ............. n/2^k

-> now the loop will stop when end value is 1

n/2^k = 1
=> n=2^k
=> log n= log 2^k
=> log n = k log 2 # as per log law, power comes front
=> k = log n / log 2
=> k = log₂n # here we assume base is 2
=> k= log n # ignoring base/constant

So
Time complexity is: O(log n)
```
